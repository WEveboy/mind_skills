# M3 反馈设计

- revision：1；active，定性控制方案。
- R：S3 §1.2—1.3 PDF 22—23、§1.7—1.9 PDF 38—45、§5.6 PDF 207—208；S2 PDF 231—232（印刷213—214）。
- I：一次设定难以抵御未知干扰，观测目标偏差后逐步调整可能积累控制效果。必须同时有合适目标、观测和有效动作；名义上有反馈并不等于稳定。
- A1 原例：S3 PDF 39—42，鹰捕兔的连续位置修正。这里抽取观测—比较—动作的机制，不复用军事应用。
- A2：有明确可观察目标、至少一个可控制动作；对完全不可控对象输出影响范围和信息需求，不编造控制权。

## E 执行契约

1. 输入目标、当前状态、可观测量、可控动作、响应时间、代价；缺一则指出它影响哪个环节。
2. 将目标写成允许区间及有效期限，区分用户真正目标与代理指标。不要求把任何质性目标强行变成数字。
3. 写清“观测者 → 指标及误差 → 比较标准 → 执行者 → 动作范围 → 响应 → 再观测”。明确谁能做，什么需要另行授权。
4. 偏差 e = target-observed 只是记号；依据实际对象确认动作增减的方向。不能对库存、温度、人员等一律套同一动作符号。
5. 给动作上限、观察窗口和安全停止线。等待依据对象延迟及数据分辨率；未知就先测响应，不虚构精确频率。
6. 动作后记录外部干扰；未过响应窗口不频繁加码。若偏差反复换向，先检查测量噪声、延迟、动作过大、目标冲突和能力饱和，优先减小步幅或暂停试验。
7. 预先约定成功、无效及停止条件；不为过关事后下调目标。保留原方案作为比较基线。

输出：一份可执行但尚待授权的反馈计划；完成标准是每个环节有责任主体或明确缺口。

- B：没有对象模型不能给通用最优增益；负反馈不必然收敛；反馈信息可能被指标激励扭曲。不得将定性方案称为工程稳定性证明。
