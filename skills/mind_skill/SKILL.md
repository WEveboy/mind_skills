# mind_skill · 四种思考的协作

先找用户当前需要完成的任务，再选择方法。不要把四本书的术语全部套进每次回答。

## 输入与路由

最低输入是一个问题或一段论证。识别目标、当前表现、时间范围、已试做法、不可变约束、可控变量、可观察数据；缺项明确写未知。只有影响下一步的缺项才询问；其余给条件化分析。

| 信号 | 先读取并执行 | 应交付 |
|---|---|---|
| 只有两个坏选项、方案同质、长期卡住 | [M1 重构与发散](references/lateral.md) | 假设表、不同机制的方案、验证办法 |
| 越改越糟、反复反弹、局部指标好而整体差 | [M2 结构诊断](references/systems.md) | 边界、存流、带依据的回路、竞争解释 |
| 有目标却难落地、调整过猛、反馈无效 | [M3 反馈设计](references/control.md) | 目标区间、观测与动作、等待和停止条件 |
| 内部原因不明、多个解释都能说通 | [M4 黑箱辨别](references/inquiry.md) | 假说及区分它们的观察或实验 |
| 判断是否成立、审查文章或决策理由 | [M5 论证审查](references/logic.md) | 前提、结论、有效性、证据缺口、修正版 |

综合任务按瓶颈选择路径：先澄清命题；问题本身不清时先 M1，反复失效时先 M2；需要执行时接 M3；机制无法分辨时接 M4；行动前以 M5 检查最关键理由。上述组合是本项目综合，不是四位作者共同提出的统一理论。

## 共用执行纪律

1. 分开事实、解释、价值选择和建议；用户给出的断言也可能需要核验。
2. 发散时暂缓筛选，但保留现实约束；收敛时检查证据和可行性。创意的生成方式不能证明创意正确。
3. 回路图中的每条因果边注明已知依据或“待检验”；符号表示同向/反向变化，不表示好坏。不要把相关性画成已证因果。
4. 用时间展开循环：本期状态影响下期行动，下期行动再改变状态。这与同一时刻的循环论证不同。
5. 找一个能推翻当前解释的观察；若观测区分不了假说，结论是信息不足，不能强选赢家。
6. 提案止于用户授权范围。分析与试验设计不自动授权现实操作。

## 输出与完成标准

用用户能检查的语言给出：当前判断及信心依据 → 关键推理或结构 → 可选方案及代价 → 最小下一步 → 何时看什么、何时停止。单纯论证审查不强加行动计划。只给与问题有关的表或图。

必须能回答：哪些是已知，哪些是猜测；哪个约束可能改变判断；下一项证据怎样区分解释。缺数据时可以完成“条件化分析”，不能报告已验证真实世界成效。
